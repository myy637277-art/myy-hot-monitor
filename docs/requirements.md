# 热点监控需求

本地运行的 AI 热点监控。多来源采集后合并成一条故事，用中文展示，并按关键词提醒。

## 采集

来源包括微博热搜、B 站热门、Hacker News、RSS、GitHub、arXiv、搜索结果页和 twitterapi.io。关键词搜索走搜狗或 DuckDuckGo，以及已配置的 twitterapi.io。搜索间隔至少 90 秒，再加 0–30 秒抖动。每个搜索引擎每天最多 80 次，推文每天最多 150 条。

「立即采集」马上返回，采集在后台继续。某个来源卡住时记为失败，其他来源照常进行。

## 去重与阅读

同一事件按网址和 SimHash 合并，并保留各个来源。X 只按同一条推文的规范网址合并，不因标题相似并入其他来源。当前不调用向量接口。

标题和来源徽章指向该来源的 http 或 https 地址，在新标签打开。没有这类地址时，文字保持不可点。

## 热度与可信度

热度只按规则计算：来源数量、条目数量、热榜和时效。可信度先算规则分（域名信誉、跨源印证、官方域名、仿冒和诈骗用语）。有模型分时，与规则分折中。仿冒、黑名单或诈骗用语把最终可信度封顶在 30。

## 分析

分析走 DeepSeek 官方接口：`https://api.deepseek.com` 的 `POST /chat/completions`。密钥是服务器上的 `DEEPSEEK_API_KEY`，只在后端读取。

模型先用 `deepseek-v4-flash`。接口若拒绝这个 id，再改用 `deepseek-flash`。不用 `deepseek-v4-pro`。`deepseek-chat` 和 `deepseek-reasoner` 已过停用日期，不再作为主模型。

这一次调用关闭思考，用 JSON 输出同时给出中文摘要和可信度。提示词要求模型返回 JSON。本地不设每日请求上限。

规则先跑。只有新故事（还没打分，或内容更新晚于上次打分）和命中关键词的故事会发给模型。没有密钥时只走规则，也不改写已经打过分的故事。调用失败时保留已有摘要，并停掉这一轮剩余的模型调用，采集本身不中断。

## 关键词与通知

监控页可以添加、暂停和删除关键词。匹配不区分大小写：整句出现，或关键词里至少 4 个字符的英文词出现在标题、中文摘要或原文片段里。一次采集没有命中时，页面写明「这次采集没有命中关键词。」

命中后记一条站内通知。配置了 Server酱 才发微信；失败时记下 HTTP 状态，页面不显示密钥。不发邮件。
