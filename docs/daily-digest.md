# 定时日报

每天到点推一份中文日报到微信。范围、时间都在设置页，存在本地 SQLite 里。没有内容就不发。

## 做了什么

设置页有一张「日报」卡片：北京时间的时和分、是否包含首页当天故事、是否包含当天的关键词命中、是否每天推送。按钮是「保存」和「立即发送日报」。

后端是 Express 里的 croner。进程启动时读 SQLite，每天推送开着就挂上一个任务；保存设置后按新时间重新挂。关掉每天推送就卸掉任务。时区是 `Asia/Shanghai`。错过那个分钟不会补发，重启也不会把漏掉的一次补上。

推送走已经在用的 Server酱。密钥仍是服务器上的 `SERVERCHAN_SENDKEY`，页面和日志都不出现密钥。

接口：

- `GET /api/v1/digest` 读当前设置
- `PUT /api/v1/digest` 保存时间、开关和两个范围，并重新挂定时任务
- `POST /api/v1/digest/send` 按已保存的范围立刻发一次

「日报」导航页还没有历史列表。推送时间和范围在设置页。

## 默认

第一次读到没有配置行时，写入 `digest_schedule` 里 id 为 `default` 的一行：

- 时间 08:00（`hour` 8，`minute` 0）
- `include_home` 开
- `include_keywords` 关
- `enabled` 关

所以装好之后不会自己开始推。要自己打开「每天推送」并保存。

## 范围

「当天」是发送那一刻的上海日历日，不是滚动 24 小时。

**首页当天故事。** 先走和首页同一套卡片：近 7 天、有发布时间、微博和 B 站不出现、搜索结果只留权威站点。X 在入库前已经筛过（官方账号或粉丝不少于 10 万，浏览量不少于 1000）。模型开着时，还没判完的故事先不进日报，和首页一样。然后只留「最新一条来源的发布时间」落在当天的故事。不先截成首页那 15 条再滤日期，避免当天的故事被更早、来源更多的故事挤掉。

**关键词命中。** 要另外勾选。取 `notifications` 里 `created_at` 落在当天的记录，按时间从新到旧，同一条故事只留一次。已经出现在首页范围里的不再重复。这类命中即使上不了首页（例如微博）也会写进去。

两条范围可以单独开。都关掉时，日报是空的。

## 正文

标题是 `热点日报` 加日期，例如 `热点日报 2026-10-28`。Server酱 标题仍去掉换行并截到 32 字。

每条三行：序号和标题、一行摘要、来源链接。标题优先用带汉字的中文事件句，否则用故事标题。摘要优先 `summary_zh`，否则用原文摘要，空白折成一行，最长 80 字；两边都没有就写「无摘要」。链接取该故事里第一条 `http` 或 `https` 地址。

首页条目在前，关键词条目补在后面。一共最多 15 条。

## 什么时候真的发出去

定时任务只在「每天推送」开着、并且 `last_sent_on` 还不是今天时才会组日报。

- 零条：不调用 Server酱，也不把今天写成已发送。页面状态是 `empty`。
- 没有密钥：不发请求。状态是 `unconfigured`。
- Server酱 返回成功：状态 `sent`，并把 `last_sent_on` 写成今天的上海日期。同一天的定时任务再跑会直接跳过。
- 请求失败或超时：状态 `failed`，可记下 HTTP 状态。不写 `last_sent_on`。croner 当天不会再响，要再发就用「立即发送日报」。

「立即发送日报」会先把卡片上的勾选存进去，再发。它不看「每天推送」有没有开，也不写 `last_sent_on`，所以不占用当天那一次定时。同一天里先手动再定时，会收到两份。

日志只写模式、结果、条数和 HTTP 状态，例如 `[digest] scheduled empty count=0`。密钥在 Server酱 的 URL 里，失败时也不把异常对象打出来。

## 存在哪

表 `digest_schedule`，迁移是 `server/drizzle/0006_digest.sql`。一行就够：

| 列 | 含义 |
|---|---|
| `id` | 固定 `default` |
| `enabled` | 每天推送 |
| `hour` / `minute` | 北京时间 |
| `include_home` / `include_keywords` | 两个范围 |
| `last_sent_on` | 上次定时发送成功的上海日期 |
| `last_status` | `sent`、`empty`、`unconfigured`、`failed` 或 `skipped` |
| `last_http_status` | 失败时的 HTTP 状态，没有则为空 |
| `updated_at` | 上次写入时间 |

cron 表达式是 `0 分 时 * * *`，6 段，时区 `Asia/Shanghai`，`protect` 开着，避免上一次还没结束又叠一次。代码在 `server/src/notify/digest.ts` 和 `server/src/scheduler.ts`。
